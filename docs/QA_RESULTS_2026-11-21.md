# 문연 QA 결과

2026-11-21 · 검증 기준 `f8d350f`의 앱 코드 · [QA 체크리스트](QA_CHECKLIST.md)

**문제 6건을 재현했다.** 빌드와 자동 테스트 4개는 모두 통과했다. 긴 문서는 창을 좁히거나 확대했을 때 끝부분이 잘렸고, 일부 PDF의 변환 본문은 원문과 달라졌다. 마감과 수강 제외는 서버에서 처리됐지만 이미 열려 있던 화면에는 상태가 바로 반영되지 않았다.

## 환경과 데이터

- Node.js 26.6.0에서 빌드와 자동 테스트를 실행했다. 학생·교수자 흐름은 macOS Chrome에서 점검했고, Safari에서 문장 강조, DOCX 업로드, 변환 대화상자를 확인했다.
- 학생·교수자 조작은 별도 로컬 예시 SQLite에서 진행했다. Word DOCX, Word에서 내보낸 PDF, 한컴에서 인쇄로 저장한 PDF, Chrome 인쇄 PDF에는 QA용 한국어 보고서를 사용했다.
- 모의 모델을 켠 상태와 끈 상태를 별도 DB에서 확인했다. 시안 서버 DB는 읽기 전용으로 스냅샷을 받아 로컬 사본에서 이전을 검증했다.

| 4 | `teacher` · `#/c/1/s/1/a/1/edit` → `student` · `#/a/1`, `#/a/1/confirm` | 교수자가 마감을 1~2분 뒤로 설정하고 학생은 편집과 제출 확인 화면을 열어 둔다. 마감 시각이 지나면 읽기 전용 상태로 바뀌어야 하지만 기존 화면에서 입력란과 제출 버튼이 계속 활성 상태다. 제출 API는 즉시 409를 반환했고, 새로고침하면 읽기 전용 화면에서 마감 전에 저장한 초안을 확인할 수 있다. |

| 6 | `teacher` · `#/c/1/settings` → `student` · `#/list` | 교수자가 학생을 과목 수강 명단에서 뺀 뒤 학생의 기존 탭에서 과제 목록으로 이동한다. 목록 API에서는 제거된 과제가 빠졌지만 화면에는 새로고침할 때까지 남았다. 기존 제출물은 보존됐고, 학생을 다시 등록한 뒤 교수자 검토 화면에서도 열렸다. |

| 앞 문단 삽입·삭제 | **통과.** 기존 강조가 원래 문장을 따라갔다. |
| 연결 문장 삭제와 위치 다시 지정 | **통과.** `위치 확인 필요` 안내가 뜨고 다른 문장에 다시 연결할 수 있었다. |
| 긴 글 붙여넣기 | **통과.** Chrome 100%에서 4,222자 붙여넣기 직후 마지막 문장의 강조를 확인했다. |
| 확대율과 창 너비 변경 | **문제 1.** 90%·110%·125%에서 확인했다. 줄바꿈이 늘어난 110%·125%와 좁힌 창에서 편집 영역 높이가 갱신되지 않았다. |
| DOCX의 제목·문단·목록 | **문제 3.** 제목과 문단, 목록 항목은 각각 나뉘지만 Word 자동 번호가 빠졌다. |

| 스캔 PDF·HWP·10 MB 초과 안내 | **통과.** 이미지형 PDF 미지원, 지원 확장자, 10 MB 이하 제한이 각각 표시됐다. |

| 한글 원본 파일 다운로드 | **통과.** 교수자 화면에서 받은 파일명과 파일 내용이 원본 DOCX와 일치했다. |
| Safari·Windows Chrome | **부분 확인.** macOS Safari에서 강조, DOCX 업로드, 변환 대화상자를 확인했다. Windows Chrome은 미검증이다. |
| 실제 iPhone·Android | **미검증.** Chrome에서 iPhone 13·Pixel 7 화면 크기를 에뮬레이션해 탭 전환을 확인했다. 실제 기기의 터치 텍스트 선택과 키보드 가림은 확인하지 못했다. |

### 학생·교수자 사용성

| 항목 | 결과 |
| --- | --- |
| 학생 로그인 직후 작업실 | 데스크톱에서 진행 중 과제의 작업실이 바로 열렸고 문서 제목·본문 입력 위치를 찾기 쉬웠다. |
| 대화 선택에서 문장 연결까지 | 연결 흐름과 마우스 드래그를 확인했다. `문서에 연결`은 답변을 선택한 뒤 나타나 첫 화면에서 순서를 파악하기는 어려웠다. |
| 지금 단계·도움 유형과 제한 경고 | 단계와 도움 유형 선택을 확인했다. 제한 유형에서 전송 전에 힌트로 안내하고 교수자 확인 항목에 기록한다는 문구가 보였다. |
| 유사 대화·연결·이의 | 연결과 이의 등록에 성공했다. 표현의 유사성이며 제출 시 교수자와 공유된다는 설명이 붙는다. `겹침 %`를 AI 사용 가능성으로 해석할 여지는 있다. |
| 수정 중 표시와 제출 회차 | 회차 선택으로 이전 본문과 재제출 본문을 구분할 수 있었다. 활용 기록만 고친 경우에는 **문제 5**가 발생했다. |
| 교수자 과목·분반·과제·학생 이동 | 과목부터 학생 제출물까지 들어가고 상위 단계로 돌아오는 경로를 확인했다. |
| 원본 보기·AI 활용 표시·범례 | 두 보기 모드를 전환할 수 있었다. 구상·자료 조사·초안 작성·수정·점검을 색과 밑줄 모양으로 구분할 수 있었다. |
| 근거·기준 확인·구술 질문 | 근거에서 기록을 골라 질문을 작성·저장했고, 기준 확인 탭에서 확인 상태를 바꿀 수 있었다. |
| 자동 분석과 학생 기록의 구분 | 각각 별도 제목과 설명이 있었다. 자동 분석 설명은 표현이 겹치는 정도를 표시한다고 명시한다. |

### 경계 상황과 시안 DB

| 항목 | 결과 |
| --- | --- |
| 같은 과제를 두 탭에서 편집 | **통과.** 두 번째 탭에서 충돌 안내와 새로고침 버튼이 나왔고, 새로고침하면 첫 번째 탭에서 저장된 본문이 표시됐다. |
| 재제출 후 이전 질문 | **통과.** 3회차 제출물의 기록으로 질문을 만든 뒤 4회차로 재제출하자 기존 질문에 `3회차 기준`이 표시됐다. |
| 시작 후 마감 통과 | 서버가 즉시 제출을 막고 저장한 초안을 보존했다. 이미 열린 화면 갱신은 **문제 4**를 참고한다. |
| 조기 마감·다시 공개 | **통과.** 학생 화면을 다시 열어 마감 시 읽기 전용, 재공개 후 편집 가능 상태를 확인했다. |
| 수강 제외와 제출물 보존 | 목록 API에서 과제가 빠지고 기존 제출물이 보존됐다. 기존 학생 탭의 목록 갱신은 **문제 6**을 참고한다. |
| 과목 AI 설정·강의자료 재반영 | **통과.** 과제 설정을 다시 저장하자 변경한 학습 목표가 새 과제 버전에 저장됐고, 모의 모델 응답에 새 참고 자료가 표시됐다. |
| 모의 모델 비활성 | **통과.** `AI 대화 꺼짐` 안내를 확인했고 외부 AI 활용 기록을 붙여 1회차를 제출했다. |
| 시안 DB 자동 이전 | **통과.** 로컬 사본에서 SQLite 무결성과 외래 키 검사를 통과했다. 이전 전후의 제출물 1건의 제목·본문과 질문 1건의 내용이 교수자 조회 API에서 일치했다. |
