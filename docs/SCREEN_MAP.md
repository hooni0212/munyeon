# 문연 화면 지도와 상태 목록

2026-11-21 · 기능 구현 전 정보 구조 확정용

[MVP 백엔드 명세](MVP_BACKEND_SPEC.md)와 2026-11-21 팀 피드백 9개를 합쳐 역할별 화면, 이동 경로, 화면 상태를 정리한다. 이 문서의 목적은 시각 디자인이 아니라 **어떤 화면이 있고 무엇을 담는지**를 고정하는 것이다. 색·여백·문구 다듬기는 기능 구현 뒤 UX 단계에서 한다.

## 0. 피드백 반영표

| --- | --- | --- | --- |

## 1. 공통 개념

**활용 항목**은 학생이 "이 부분에서 AI를 이렇게 썼다"고 남기는 기록 하나다. 피드백 2·7·9가 모두 이 단위를 기준으로 동작한다.

| 필드 | 내용 |
| --- | --- |
| 위치 | 초안 버전의 `paragraphId`와 문단 안의 `start`·`end` 글자 위치, 선택 당시 원문 `quote`. 문단 전체를 고르면 범위가 문단 전체. 위치 없음 = 미반영 항목 |
| 연결 대화 | 문연 대화 0개 이상. 0개면 외부 AI 도구 활용을 직접 적은 항목 |
| 활용 단계 | 하이라이트 색상의 기준. 기본안: `구상`, `자료 조사`, `초안 작성`, `수정·점검` (과제 설정에서 교수자가 이름 변경 가능) |
| 활용 방식 | 명세의 `idea`, `direct`, `reworked`, `not_adopted` |
| 학생 설명 | 무엇을 받아들이고 무엇을 바꿨는지 |

본문을 수정해 범위가 흔들리면 `quote`로 위치를 다시 찾고, 찾지 못하면 **위치 확인 필요** 상태로 표시해 학생이 다시 지정하게 한다.

## 2. 학생 화면

### 2.1 이동 경로

```
로그인 → 작업실(최근 과제 또는 마감 임박 과제)
            ├─ 왼쪽 사이드바: 과목별 과제 목록 (접기/펼치기)
            ├─ 과제 안내 (작업실 상단 버튼 → 오버레이 또는 별도 화면)
            ├─ 제출 준비 → 제출 확인 → 제출 완료
            └─ 제출 완료 후 마감 전이면 → 작업실로 돌아가 수정 → 다시 제출
```

별도 "내 과제" 홈은 모바일과 과제가 없는 경우에만 쓴다. 데스크톱에서는 사이드바가 홈 역할을 한다.

### 2.2 작업실

```
┌──────────┬─────────────────────┬──────────────────────────────┐
│ 내 과제 « │ 과제 AI             │ 문서 편집기   [파일 올리기]    │
│ ▾ 창의융합 │ 지금 단계: [구상 ▾]  │ 제목                           │
│  ● 보고서 │ ┌─────────────────┐ │ 문단 1 …… ▓▓강조된 문장▓▓ …   │
│  ○ 과제2  │ │나: …            │ │ 문단 2 ……                      │
│ ▸ 다른과목 │ │AI: …  ☐ 선택    │ │                                │
│          │ └─────────────────┘ │ ─ 연결 모드: 문장을 선택하세요 ─ │
│          │ [선택 2개 · 문서에 연결]│        [취소]                  │
└──────────┴─────────────────────┴──────────────────────────────┘
            상단: 과제명 · 마감 · 저장 상태 · [과제 안내] [제출 준비]
```

- **사이드바(#1):** 과목별 그룹, 과제마다 상태(작성 중·제출됨·마감)를 표시한다. 접으면 아이콘 폭만 남는다.
- **문서에 연결(#2, #9):** 대화마다 체크박스가 있다. 하나 이상 선택하면 하단에 `선택 N개 · 문서에 연결`이 나타난다. 누르면 편집기가 연결 모드로 바뀌고, 학생이 문장을 드래그하거나 문단 번호를 누르면 활용 항목이 생긴다. 단계와 방식은 대화의 단계를 기본값으로 넣고 바로 수정할 수 있게 한다. 설명은 제출 준비에서 채워도 된다.
- **편집기 하이라이트:** 학생 편집기에도 활용 항목 범위를 단계 색으로 표시한다. 일반 `textarea`는 내부 강조가 안 되므로, 같은 글꼴의 미러 레이어를 뒤에 겹치는 방식으로 구현한다(본문 데이터는 지금처럼 평문 유지).
- **파일 올리기(#3):** `.txt`, `.pdf`, `.docx` 허용. 서버가 텍스트를 추출하면 **변환 미리 보기**에서 문단 나뉨을 확인한 뒤 본문에 반영한다. 원본 파일은 초안 버전에 첨부로 남는다. 이미지형 PDF는 "텍스트를 찾지 못했어요"로 안내한다.

### 2.3 제출 준비 → 확인 → 완료

기존 `AI 활용 확인 → 활용 사례 연결` 두 단계를 **제출 준비** 한 화면으로 합친다. 연결은 작업실에서 이미 끝냈기 때문이다.

- 활용 항목 목록: 위치 미리보기, 연결 대화, 단계, 방식, 설명(필수). 설명이 빈 항목은 제출을 막는다.
- 추가 버튼: `문서에 반영하지 않은 활용 추가`, `외부 AI 활용 직접 기록`.
- 항목이 하나도 없으면 `이 과제에서 AI를 사용하지 않았어요` 확인이 필요하다.
- **재제출(#4):** 제출 완료 화면에 `제출 1회차 · 마감 전까지 다시 제출할 수 있어요`를 표시한다. 작업실은 마감 전까지 계속 편집할 수 있고, 상단에 `제출본과 다른 수정 내용이 있어요` 상태를 보여준다. 재제출하면 회차가 늘고, 이전 회차는 학생도 읽기 전용으로 열람한다.

### 2.4 학생 화면 상태

| 화면 | 상태 |
| --- | --- |
| 사이드바 | 과목 없음, 과제 없음, 비공개 과제 숨김, 마감됨 |
| 채팅 | AI 꺼짐, 응답 대기, 실패·재시도, 제한된 요청 안내, 제출 후 읽기 전용(마감 후) |
| 편집기 | 저장 중·저장됨·저장 실패, 변환 중·변환 실패·미리 보기, 연결 모드, 위치 확인 필요 항목 있음 |
| 제출 | 미제출, 제출됨(마감 전·수정본 있음/없음), 마감됨, 마감 후 제출 차단, 중복 요청 |

## 3. 교수자 화면

### 3.1 이동 경로(#5)

```
내 과목 ─ 과목 카드 안에 분반 목록이 바로 보임
   └─ 분반 선택 → 과제 목록 (상태·마감·제출 수)
         └─ 과제 선택 → 학생 제출 현황 (분반 명단 + 제출 상태)
               └─ 학생 선택 → 검토 작업실
과목 설정: 수강 명단 · 분반 · 과목 AI 설정 · 강의자료  (과목 단위)
과제 설정: 내용 · 마감 · 대상 분반 · AI 활용 기준 · 공개  (과제 단위)
```

- 과제는 과목에 속하고 대상 분반을 하나 이상 고른다. 같은 과제를 여러 분반에 내는 경우가 많기 때문이다.
- 과목 카드에서 분반을 바로 고르게 해서 네 단계 계층을 세 번의 클릭으로 줄인다.
- 상단에 `과목 › 분반 › 과제 › 학생` 경로 표시를 두고, 각 단계로 바로 돌아갈 수 있게 한다.

### 3.2 검토 작업실

```
┌──────────┬────────────────────────────────┬─────────────────────┐
│ 학생 목록  │ [원본 보기 | AI 활용 표시]  제출 2회차▾ │ [근거] [질문 3]       │
│ 필터·검색  │ [원본 파일 받기]                   │                     │
│ ● 김하윤  │ 문단 1 …… ▓구상▓ ……               │ 선택한 범위의 활용 항목 │
│ ○ 박서준  │ 문단 2 …… ▓초안 작성▓ …          │  - 연결 대화 원문     │
│ − 이유진  │                                │  - 학생 설명         │
│          │ 범례: ■구상 ■자료 ■초안 ■수정      │  [이 부분으로 질문 작성]│
└──────────┴────────────────────────────────┴─────────────────────┘
```

- **보기 전환(#7):** `원본 보기`는 표시 없이 학생이 쓴 그대로를 보여준다. `AI 활용 표시`는 활용 항목 범위를 단계 색으로 강조한다. 색만으로 구분하지 않도록 밑줄 모양이나 단계 이름 표시를 함께 쓴다. 강조를 누르면 오른쪽 `근거` 탭에 해당 항목이 열린다(현재 동작 유지).
- **원본 파일(#6):** 학생이 파일을 올렸으면 `원본 파일 받기`를 표시한다. 업로드 이후 본문이 수정됐다면 `업로드 후 수정됨`을 함께 표시한다.
- **제출 이력(#4):** 회차 선택에서 이전 제출본을 읽기 전용으로 연다. 회차 간 차이 비교는 P1.
- **질문 패널(#8):** 오른쪽 패널의 두 번째 탭. 질문 여러 개를 목록으로 두고, 각 질문은 근거(문장 범위·활용 항목)를 갖는다. 근거 탭에서 `이 부분으로 질문 작성`을 누르면 질문 탭에 근거가 채워진 새 질문이 열린다. 별도 구술 질문 화면은 없앤다.
- **기준 확인 항목:** 명세의 `policy_events`는 근거 탭 상단에 `기준 확인 N건`으로 모아 보여준다.

### 3.3 교수자 화면 상태

| 화면 | 상태 |
| --- | --- |
| 과목·분반·과제 목록 | 과목 없음, 분반 없음, 과제 없음, 과제 초안·공개·마감 |
| 제출 현황 | 미제출, 제출됨(마감 전이라 바뀔 수 있음), 재제출됨, 검토 중, 질문 준비 완료 |
| 검토 작업실 | 활용 항목 없음(AI 미사용 신고), 위치 확인 필요 항목, 원본 파일 없음, 이전 회차 열람 중(읽기 전용) |
| 질문 패널 | 질문 없음, 추천 대기·실패, 이전 회차 기준으로 작성된 질문 |

## 4. 데이터·API 변경 요약 (명세 대비)

| 추가·변경 | 내용 |
| --- | --- |
| `course_sections` | `courseId`, 분반 이름. `course_enrollments`에 `sectionId` 추가 |

| 업로드 API | `POST /assignments/{id}/draft/import` (multipart) → 변환 텍스트 미리 보기 반환, `GET /files/{fileId}` 권한 검사 후 원본 다운로드 |

PDF는 `pdfjs-dist`, DOCX는 `mammoth`로 텍스트를 추출하는 것을 기본안으로 한다.

## 5. 결정이 필요한 항목 (기본안)

| 항목 | 기본안 | 이유 |
| --- | --- | --- |
| 구술 질문 개수 | 여러 개 | 명세와 같고, 질문 패널 통합(#8)과 맞음 |
| 구술평가 점수 화면 | 유지하되 검토 작업실 질문 탭 안의 접힌 영역으로 이동 | 이미 구현돼 있고 별도 화면을 줄이는 방향과 맞음 |
| AI 모델 | 개발·시연은 모의 모델 켜기, 배포 기본값은 꺼짐 유지 | 채팅·연결·추천 흐름을 끝까지 확인하려면 응답이 필요 |
| 업로드 후 본문 편집 | 허용하고 교수자 화면에 `업로드 후 수정됨` 표시 | 변환 오류를 학생이 고칠 수 있어야 함 |
| 재제출 후 기존 질문 | 유지하고 `이전 회차 기준` 표시 | 교수자가 작성한 내용을 잃지 않게 함 |
| 활용 단계 이름 | 구상·자료 조사·초안 작성·수정·점검 | 과제마다 교수자가 바꿀 수 있게 함 |

## 6. 구현 순서

화면은 기존 컴포넌트 수준으로만 붙이고 시각 다듬기는 하지 않는다.

1. **과목·분반·과제·수강 경계.** 스키마 버전, 권한 검사, 교수자 탐색(#5), 학생 사이드바(#1).
2. **초안·제출 회차와 파일.** 초안 버전·문단 ID, 재제출(#4), 업로드 변환·원본 보관·다운로드(#3, #6).
3. **활용 항목.** 채팅 다중 선택과 문서에 연결(#2, #9), 편집기 하이라이트, 제출 준비 한 화면.
