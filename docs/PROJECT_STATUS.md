# 문연 목표와 진행 현황

기준일: 2026-11-21. 이 문서는 현재 소스 코드, 자동 테스트, 로컬 화면 확인을 근거로 작성했다. 장기 목표와 다음 단계는 구현 상태와 구분한 제안이며, 실제 수업 도입이나 교육 효과가 입증되었다는 뜻은 아니다.

## 2026-11-21 과목 구조 재구성과 MVP 기능 구현

[MVP 명세](MVP_BACKEND_SPEC.md)의 부족한 부분을 [화면 지도](SCREEN_MAP.md)의 기본안으로 채워 구현했다. 시각 디자인 다듬기는 기능 확인 뒤 별도 단계로 둔다.

- **구조:** 과목·분반·수강 명단·과제(공개 전/공개/마감)·공개 버전. 교수자는 자기 과목만, 학생은 자기 분반에 공개된 과제만 접근한다. 기존 단일 과제 DB는 자동 이전한다.
- **학생:** 접이식 과제 목록, 단계·도움 유형을 고르는 과제 AI(제한 조합은 모델 없이 안내), 대화 여러 개를 문장·문단에 연결하는 활용 기록과 단계별 색 강조, `.txt`·`.pdf`·`.docx` 업로드·변환 확인, 제출 준비 한 화면(설명·미반영·외부 AI·자동 유사 대화 연결/이의·AI 미사용 확인), 마감 전 재제출과 회차 이력.
- **교수자:** 과목 → 분반 → 과제 → 학생 탐색, 과목 AI 설정·강의자료·명단 관리, 단계×도움 유형 기준표, 검토 작업실의 원본 보기/AI 활용 표시 전환, 근거·기준 확인·구술 질문 탭 통합, 질문 여러 개(추천·직접·수정·선택), 확인 필요 표시, 회차 선택, 원본 파일 다운로드.
- **AI:** 로컬 체험은 모의 모델, 운영 기본값은 꺼짐. 자동 유사 대화 분석은 모델 없이 글자 3-gram 겹침으로 계산하며 AI 사용 여부를 판정하지 않는다.
- **API:** `/api/v1`, 오류 `code`, 초안·과제 설정의 `revision` 충돌(409), 채팅·제출 요청 ID 중복 방지.
- **검증:** `npm test` 4개 묶음 통과(명세 시나리오·이전 DB 이전·운영 보호·백업 복구), `npm run build` 성공, 로컬 Chrome에서 학생·교수자 전 화면 순회 시 브라우저 오류 없음, 모바일 폭 화면 확인. Chrome·macOS로 만든 PDF·Word의 한국어 텍스트 추출 확인.

명세와 다르게 단순화한 점:

- 보고서 생성 작업(`jobs`)은 두지 않았다. 유사 대화 분석이 결정적이고 빨라서 제출 준비 화면에서 즉시 계산하고, 제출 시 서버가 다시 계산해 고정한다.
- 업로드 원본은 별도 폴더가 아니라 SQLite에 저장한다. 기존 백업·복구 절차에 그대로 포함된다.
- 활용 기록의 위치는 문단 ID 대신 본문 글자 위치와 인용 원문으로 저장한다. 문장 단위 선택(#2)을 위해서다.

## 2026-11-20 화면 재구성

- React 화면을 [과제 작업실 시안](prototypes/munyeon-workspace.html) 기준으로 다시 작성했다. 이전 흑백 화면과 단계형 시안(`munyeon-flow.html`)은 제거했다.
- 학생: 내 과제 → 과제 안내 → 작업실(내 과제·과제 AI·문서 편집기) → AI 활용 확인 → 활용 사례 연결 → 제출 확인 → 제출 완료. 초안과 AI 활용 선택은 서버에 자동 저장한다.
- 교수자: 학생 제출 현황(상태별 집계·검색·필터, 미제출 포함) → 검토 작업실(학생 목록·제출물·AI 활용 근거, 이전·다음 학생) → 구술 질문 → 구술평가, 과제 설정 → AI 활용 기준.
- 화면 위치를 주소(`#/write`, `#/review/3` 등)에 남겨 새로고침·뒤로가기·링크 공유가 가능하다.
- API 변경: `GET·PUT /api/draft`, `GET /api/roster`, `PUT /api/submissions/:id/question`을 추가했다. 문항 목록·확정용 `POST /questions`, `PATCH /questions/:id`, `PUT /confirm`과 제출 목록 `GET /api/submissions`는 제거했다.
- 과제 설정 항목을 제목·과목·분반·마감·과제 안내·허용하는 도움·제한하는 도움·구술평가 기준으로 바꿨다. 기존 DB의 설정과 근거 기록은 서버 시작 시 새 형식으로 변환한다.

## 2026-11-20 시안 업데이트

- AI 모델은 현재 범위에서 제외했다. 서버 기본값은 `MUNYEON_AI_ENABLED=0`이며 학습실·추천 버튼을 숨긴다. 향후 연결 코드는 보존한다.
- 학생의 과제 안내·제출과 교수자의 직접 질문·평가 흐름을 기존 글숲 홈서버의 별도 서비스로 배포했다.
- 무료 HTTPS 주소와 개별 계정, 서버 Node.js 24 테스트, 실제 API 접근 제어·수동 평가 저장·재시작 보존을 확인했다.
- Canvas는 공식 문서로 연동 가능성을 검토했다. 학교 키·LTI 등록·실제 학생 자료 연동은 아직 하지 않았다.
- 아래 초기 기능 표의 AI 관련 항목은 보존된 구현 현황이며 현재 시안 활성 기능이 아니다.

## 프로젝트가 해결하려는 문제

AI를 사용할 수 있는 과제에서 학생이 어떤 도움을 받았고 최종 판단을 어떻게 내렸는지 설명할 수 있도록 한다. 교수자는 과제의 허용 범위를 정하고 제출물의 실제 문단을 근거로 구술 질문을 준비한다. 마지막 평가는 교수자가 학생의 설명을 듣고 직접 기록한다.

전체 대화를 감시하거나 AI 사용 여부를 자동 판별하는 시스템은 현재 목표에 포함하지 않는다. 교수자 화면에는 학습 도움 유형과 학생이 선택해 공유한 답변·자기보고가 표시된다. 서버에는 학습 대화가 저장되므로, 교수자 화면의 열람 제한과 운영자의 데이터 접근 가능성은 구분해야 한다.

## 목표 범위

1. **핵심 MVP:** 교수자 지침 설정 → 학생 AI 학습 → 선택적 사례 공유와 과제 제출 → 문단 기반 질문 작성·확정 → 구술평가 저장까지 연결한다.
2. **소규모 수업 시범 운영:** 디자인을 정리하고 실제 모델·HTTPS 서버·개별 계정·백업 복구를 검증해 한 과제의 수업 흐름을 운영한다.
3. **확장 단계 제안:** 여러 강좌·과제, 명단과 제출 기한, 재제출 정책, 성적 내보내기, 학교 인증·LMS 연동을 다룬다. 학교 협의와 사용성 검토 후 우선순위를 확정한다.

현재 위치는 **AI 없는 서버 시안 배포 및 기본 동작 검증 완료, 실제 수업 운영 준비 전 단계**다. 작업별 규모와 최종 범위가 확정되지 않아 전체 진행률을 임의의 백분율로 표시하지 않는다.

## 현재 구조의 한계

- 시각 디자인·문구·상태 표시는 기능 확인용 수준이다. 실제 사용자 사용성 검토와 스크린리더 점검이 남아 있다.
- PDF는 텍스트가 있는 파일만 읽는다. 스캔 이미지 PDF, 표·각주 구조, 원래 서식은 보존하지 않는다. 한국어 단어가 줄 끝에서 나뉜 경우 띄어쓰기가 잘못 들어갈 수 있어 변환 확인 단계에서 학생이 고친다.
- 학생 계정은 여전히 운영자가 관리 CLI로 발급하고, 교수자는 기존 아이디로 수강 명단에 추가한다. 일괄 등록·LMS 명단 연동은 없다.
- 진행 중 과제의 기준을 바꾸면 새 버전이 즉시 공개된다. 변경 알림과 이미 제출한 학생의 재확인 절차는 없다.
- 학생의 구술 답변 기록, 평가 결과 공개, 성적 내보내기는 구현하지 않았다(P1).
- 자동 유사 대화 분석은 표현 겹침만 본다. 의역·요약된 활용은 찾지 못한다.
- 실제 모델의 지침 준수·품질·비용은 검증하지 않았다. 모의 모델 답변은 고정된 문장이다.
- SQLite 단일 앱 인스턴스 구성이며, 동시 접속 성능 목표와 측정값은 없다.

## 이번 확인 기록

- Node.js 26.6.0에서 `npm test`: 통합 테스트 3개 통과.
- 같은 환경에서 `npm run build`: Vite 프로덕션 빌드 성공.
- 프로젝트 요구사항 및 Docker 기준은 Node.js 24 이상이다. 추가 배포 확인에서는 홈서버 Node.js 24.22.1로 동일한 통합 테스트 3개를 통과했다. Docker 컨테이너 실행은 검증하지 않았다.
- 원본 `data/`와 분리한 임시 SQLite에 예시 데이터를 구성해 로컬 Chrome 화면을 확인했다. 예시 AI 답변은 화면 설명용으로 넣었으며 실제 모델 호출 결과가 아니다.
- 화면 캡처는 대화에서만 제시하며 GitHub 업로드 대상에 포함하지 않는다.
