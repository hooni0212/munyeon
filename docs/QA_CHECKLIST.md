# 문연 QA 체크리스트

2026-11-21 · 과목·분반 구조와 MVP 기능 구현(`main` 0f8d85b) 기준

자동 테스트와 헤드리스 브라우저로 확인하지 못한 부분을 사람이 직접 점검하기 위한 목록이다. 구현 내용은 [프로젝트 현황](PROJECT_STATUS.md), 화면 구성은 [화면 지도](SCREEN_MAP.md)를 참고한다.

2026-11-21 실행 기록은 [문연 QA 결과](QA_RESULTS_2026-11-21.md)에 남겼다.

## 시작

```sh
npm run build && npm start      # http://127.0.0.1:4311
```

새 예시 데이터로 시작하려면 별도 DB를 지정한다. 파일을 지우고 다시 실행하면 초기화된다.

```sh
MUNYEON_DB=data/qa.sqlite npm start
```

| 아이디 | 역할 | 예시 데이터 |
| --- | --- | --- |
| `teacher` | 교수자 | 창의융합적디자인(01·02분반), 디자인 문제 해결 보고서 |
| `teacher2` | 교수자 | 디자인 리서치 방법 |
| `student` | 학생 | 김하윤 · 두 과목 수강, 제출·기준 확인 항목 있음 |
| `student2` | 학생 | 박서준 · 외부 AI 기록으로 제출 |
| `student3` | 학생 | 이유진 · 02분반, 미제출 |

비밀번호는 모두 `munyeon-아이디`다.

## 이미 확인한 것

권한, 저장, 재제출, 마감 차단, DB 이전은 자동 테스트(`npm test`)로 확인했다. 기본 흐름(연결 → 제출 준비 → 재제출, 교수자 검토·기준 확인·질문 추천)은 1440px 헤드리스 Chrome에서 한 번 실행했다. 아래는 자동 스크립트로 판단할 수 없거나 확인하지 않은 부분이다.

## 1. 최우선: 확인하지 못한 부분

### 편집기 강조와 한글 입력

가장 깨지기 쉬운 부분이다.

- [ ] 강조된 문장 바로 앞·안에서 **한글로 입력**할 때, 글자를 조합하는 동안 강조가 어긋나지 않는다.
- [ ] 강조된 문장보다 앞쪽에 문단을 추가하거나 지워도 강조가 해당 문장을 따라간다.
- [ ] 강조된 문장을 통째로 지우면 그 기록에 "위치 확인 필요"가 뜨고, **위치 다시 지정**으로 다시 연결할 수 있다.
- [ ] 수천 자의 긴 글을 붙여넣어도 끝부분까지 강조와 글자가 맞는다.
- [ ] 브라우저 확대 90%, 110%, 125%에서, 그리고 창 너비를 바꿔도 강조와 글자가 맞는다.

### 실제 파일

- [ ] 실제로 작성한 보고서 `.docx`에서 문단·제목·목록이 기대대로 나뉜다.
- [ ] 한글·Word에서 내보낸 PDF와 브라우저 인쇄로 만든 PDF에서 띄어쓰기 깨짐, 문단 오분리, 머리말·쪽번호 섞임이 없는지 확인한다.
- [ ] 스캔 PDF, `.hwp`, 10 MB 초과 파일을 올렸을 때 오류 안내가 이해하기 쉽다.
- [ ] 변환 결과 확인 창에서 텍스트를 고친 뒤 반영하면 고친 내용이 본문에 들어간다.
- [ ] 교수자의 **원본 파일 받기**로 내려받은 파일 이름이 한글로 제대로 나온다.

### 다른 환경

- [ ] Safari와 Windows Chrome(가능하면)에서 강조, 대화상자, 파일 업로드가 동작한다.
- [ ] 실제 휴대폰(iPhone·Android)에서 터치로 문장을 선택해 연결할 수 있고, 탭 전환이 자연스럽고, 키보드가 입력창을 가리지 않는다.

## 2. 사용성: 학생·교수자로 한 바퀴씩

### 학생

- [ ] 처음 로그인했을 때(작업실이 바로 열림) 무엇을 해야 하는지 알 수 있다.
- [ ] "선택 → 문서에 연결 → 문장 드래그"를 설명 없이 찾을 수 있다. 핵심 상호작용이다.
- [ ] "지금 단계"와 도움 유형을 무엇으로 골라야 할지 알 수 있다. 제한 조합 경고가 어떻게 느껴지는지 기록한다.
- [ ] 제출 준비의 "자동으로 찾은 유사한 대화"와 연결·이의 버튼을 이해할 수 있다. 감시처럼 느껴지는지 기록한다.
- [ ] 재제출 후 "수정 중" 표시와 제출 이력에서 어느 회차가 제출된 것인지 알 수 있다.

### 교수자

- [ ] 과목 → 분반 → 과제 → 학생으로 들어가는 흐름이 자연스럽고, 상위 단계로 쉽게 돌아갈 수 있다.
- [ ] 원본 보기와 AI 활용 표시를 바꿔 볼 수 있고, 단계 색 4가지와 범례를 구분할 수 있다.
- [ ] 근거·기준 확인·질문 탭에서 "기록 선택 → 이 기록으로 질문 작성" 흐름이 자연스럽다.
- [ ] "자동 분석"과 "학생 기록"의 차이가 분명하다. AI를 사용했다는 판정으로 오해할 여지가 없는지 기록한다.

## 3. 경계 상황

- [ ] 같은 과제를 **탭 두 개**로 열고 한쪽에서 쓴 뒤 다른 쪽에서 입력하면 "다른 창에서 바뀌었어요" 안내와 새로고침 버튼이 나온다.
- [ ] 교수자가 질문을 작성한 뒤 학생이 재제출하면 기존 질문에 "1회차 기준" 표시가 붙는다.
- [ ] 교수자가 마감을 1~2분 뒤로 설정한 뒤 마감이 지나면 바로 제출이 막히고 초안은 남는다.
- [ ] 교수자가 과제를 조기 마감했다가 다시 공개할 수 있다.
- [ ] 교수자가 학생을 수강 명단에서 빼면 그 학생의 과제 목록에서 사라지고, 제출물은 보존된다.
- [ ] 과목 AI 설정이나 강의자료를 바꾼 뒤 과제 설정을 다시 저장하면 채팅에 반영된다.
- [ ] 모의 모델을 끄고(`MUNYEON_AI_MOCK=0 npm start`) 실행해도 작성·기록·제출이 AI 없이 동작한다는 점이 화면에서 분명하다.

## 4. 시안 서버 반영 전

- [ ] 현재 시안 서버의 DB 사본을 로컬로 가져와 실행하고, 자동 이전 후 기존 제출물·질문이 제대로 보이는지 확인한다. 실제 데이터이므로 **로컬에서만** 진행한다.
